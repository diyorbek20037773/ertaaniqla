# ADR-0003 — Languages, scripts and URL scheme

- Status: accepted (2026-09-15)

## Context

The TZ says only "двуязычность" (ru/uz). Uzbek is written in both Latin and Cyrillic scripts.
The audience includes elderly users in regions (often Cyrillic-literate) and younger users
(Latin). The state's official script is Latin.

## Decision

- Default language **`uz` in Latin script**; second language **`ru`**.
- `LANGUAGE_CODE = "uz"`, `LANGUAGES = [("uz", "Oʻzbekcha"), ("ru", "Русский")]`,
  `WAGTAIL_I18N_ENABLED = True`, `WAGTAIL_CONTENT_LANGUAGES = LANGUAGES`.
- URL prefix for **every** language including the default (`/uz/…`, `/ru/…`);
  `/` redirects by cookie → `Accept-Language` → default.
- Page translation via **wagtail-localize** (separate page trees per locale, per-language slugs);
  static UI strings via `.po` files; CI fails on untranslated `uz`/`ru` strings.
- `hreflang` + `x-default` in `<head>`; one sitemap per language.
- Architecture allows `uz-Cyrl` and `en` later: add to `LANGUAGES`, create the Wagtail locale,
  sync the tree — no code refactor. A `uz-Cyrl` locale stub is created in M1.
- Uzbek placeholder text must be real Uzbek (Latin, with oʻ/gʻ/ʼ), never transliterated Russian.

## Consequences

- Uzbek Latin diacritics require a font subset with U+02BB/U+02BC (spec §5); system font in the
  wireframe phase covers it.
- Search uses one Postgres text-search configuration (`ertaaniqla` = simple + unaccent) with a
  Latin↔Cyrillic normaliser and a uz/ru synonym list (M2).
